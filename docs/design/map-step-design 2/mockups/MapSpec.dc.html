Map step — states and interactions

Every state is carried by a text label and an icon; colour only reinforces it. Counts are always “started so far” — never “x of N”, never a percentage bar.

Interaction notes

Open / close the panel

  • Click, Enter or Space on the node toggles it; node has aria-expanded + aria-controls.
  • Panel opens directly under the graph card, scrolls into view if needed; focus moves to the panel heading.
  • Close (×) or Esc while focus is in the panel closes it and returns focus to the node.
  • One map panel at a time; choosing another map node swaps the content.

Filter and sort

  • Applied instantly on the client over the records already loaded; paging resets to the first 50.
  • Result line is a polite live region: “1 failed item · sorted by duration ↓”.
  • State is kept in the address (?items=failed&slow=1&sort=duration-desc&q=acct) so a shared link opens the same view.
  • “No items match.” offers “Clear search and filters”.

Show more

  • 50 rows per page. “Show more · next 50” appends the next page; focus stays on the button, new rows are announced (“50 more items shown”).
  • Below the button: how many more records remain (“101 more failed items with a record”).
  • Hidden when every matching record is shown. The list is never drawn all at once.

Open / close an item

  • Each row is one link; click or Enter opens the item at its own address …/steps/accounts/items/acct-7.
  • “slowest acct-7 (9.1 s)” opens the same view.
  • Esc or “Back to items” returns to the list with filters, scroll position and focus on that row restored.
  • Link to an item without a record shows the partial-detail message and a link to the list.

Refreshing data

  • While the run is active, poll every 5 s (“Live · updated 2 s ago”). Stop when the run ends, stalls or dies.
  • Merge by item key: counts and pills update in place; new items append in order started; rows never jump under the pointer or focus.
  • Search text, chips, sort, open panel, scroll and focused row are kept. The open item page updates its steps, timer and events the same way.
  • Percentiles appear once 5 items have finished; before that the line reads “percentiles need 5 finished items”.

Text, scale and keyboard

  • Keys, step names, errors and events are plain text in mono; long values wrap anywhere, never truncate.
  • Thousands separators on every count; “≈” on median / p95.
  • Tab order: node → close → slowest → search → chips → Slow → sort → direction → rows → Show more.
  • Touch targets ≥ 44 px on mobile; list rows stack: key + status, then where / error, then duration · in → out · flags.
